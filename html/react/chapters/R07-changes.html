7.1 この章の進め方

この章では、どのファイルをどの順で読むかを自分で選びます。これまでの章の読み方（DOM 版と並べる、props をたどる、console.log で回数を見る、リンター、Network のタブ、差分を読む、debugger; など）を使います。

場面の設定：同僚が、React 版の家計簿に「削除の確認」の機能を足しました。「削除」を押すと、すぐには消えず、「削除する」「やめる」の 2 つのボタンに変わります。同僚は、ついでに、ほかの所にも手を入れています。あなたは、この変更を読んで点検する役です。

変更の前は完成版（react/app/）、変更の後はこの章の改修用フォルダ（react/exercises/R07-changes/）です。

問題 1〜4 では、本文に載せた差分を読みます。本文の差分は、ファイル名を示す行（diff --git〜+++）と、import の行の差分を省いて載せています。

7.2 この章で初めて出る書き方

カスタムフックは、中で useState や useEffect を呼ぶ、自分で書いた関数です。名前は use で始めます。

  • コンポーネントの中の、フックを使った処理を、関数に切り出すときに使います。
  • カスタムフックは、コンポーネントか、ほかのカスタムフックの一番上で、毎回同じ順番で呼びます（第3章の 3.6）。

useRef は、画面の要素を直接つかむための入れ物を作るフックです。

  • const dateRef = useRef<HTMLInputElement>(null); で入れ物を作り（< > は型引数。本編第8章の 8.3）、JSX の要素に ref={dateRef} と書きます。
  • React が画面に要素を作ると、その要素が dateRef.current に入ります。それまでは null です。
  • 入力欄にフォーカスを当てるなど、state では表せない操作に使います。欄の文字やクラスのように画面に表示するものは、これまでどおり state で変えます。

改修：同僚の変更を仕上げる

明細を追加したときの不具合（利用者からの報告）：次の報告が届いています。原因の場所は、自分で探してください。

  • 明細を 1 件追加すると、同じ明細が 2 行、一覧に出ます。
  • しかも、ページを読み込み直すと、その明細が消えています。

確認の表示が別の行に移る不具合（差分で入ったもの）：問題 4 で見つけた不具合を直します。

絞り込みを解除するボタン（小さな機能）：月か種別で絞り込んでいるときだけ、「絞り込みを解除」のボタンを表示します。押すと、月も種別も「すべて」に戻ります。

import { monthOf } from "./summary.ts";
import type { AppState, CategoriesState, Entry, EntryKind, Filter } from "./types.ts";

export function createInitialState(entries: Entry[]): AppState {
  return {
    entries,
    filter: { month: "all", kind: "all" },
    categories: { status: "loading" },
    formKind: "expense",
    formErrors: [],
  };
}

export function addEntry(state: AppState, entry: Entry): AppState {
  return { ...state, entries: [...state.entries, entry], formErrors: [] };
}

export function removeEntry(state: AppState, id: string): AppState {
  const entries = state.entries.filter((entry) => entry.id !== id);
  const { month } = state.filter;
  const monthRemains = month === "all" || entries.some((entry) => monthOf(entry.date) === month);
  return {
    ...state,
    entries,
    filter: monthRemains ? state.filter : { ...state.filter, month: "all" },
  };
}

export function setFilter(state: AppState, changes: Partial<Filter>): AppState {
  return { ...state, filter: { ...state.filter, ...changes } };
}

export function setCategories(state: AppState, categories: CategoriesState): AppState {
  return { ...state, categories };
}

export function setFormKind(state: AppState, formKind: EntryKind): AppState {
  return { ...state, formKind, formErrors: [] };
}

export function setFormErrors(state: AppState, formErrors: string[]): AppState {
  return { ...state, formErrors };
}

import type { ChangeEvent } from "react";
import { formatMonth } from "../format.ts";
import { listMonths } from "../summary.ts";
import type { Entry, Filter } from "../types.ts";

type FilterBarProps = {
  entries: Entry[];
  filter: Filter;
  onFilterChange: (changes: Partial<Filter>) => void;
};

export function FilterBar({ entries, filter, onFilterChange }: FilterBarProps) {
  const months = listMonths(entries);
  const isFiltering = filter.month !== "all" || filter.kind !== "all";

  function handleKindChange(event: ChangeEvent<HTMLSelectElement>): void {
    const kind = event.target.value;
    if (kind === "all" || kind === "income" || kind === "expense") {
      onFilterChange({ kind });
    }
  }

  return (
    <div className="filters">
      <label>
        月
        <select value={filter.month} onChange={(event) => onFilterChange({ month: event.target.value })}>
          <option value="all">すべて</option>
          {months.map((month) => (
            <option key={month} value={month}>
              {formatMonth(month)}
            </option>
          ))}
        </select>
      </label>
      <label>
        種別
        <select value={filter.kind} onChange={handleKindChange}>
          <option value="all">すべて</option>
          <option value="income">収入</option>
          <option value="expense">支出</option>
        </select>
      </label>
      {isFiltering && <button onClick={() => onFilterChange({ month: "all", kind: "all" })}>絞り込みを解除</button>}
    </div>
  );
}
同じ明細が 2 行出た理由

開発中は、setState に渡した関数を React が同じ prev で 2 回呼び、片方の結果だけを使います。push は、1 回目に書き換えた prev.entries の配列に、2 回目も明細を足します。どちらの結果を使っても、同じ明細が 2 つ入った配列です。

  • 元の addEntry なら、2 回とも同じ「1 件増えた結果」なので、1 件だけ増えます。
  • React は開発中に 2 回呼んで、state を書き換える書き方を早く見つけられるようにしています。1 回しか呼ばれなければ、画面には正しく 1 行出て、「保存されない」ことに気づくのが遅れます。
  • 第3章の問題 4 では、push の後に同じ state を渡したので、画面が変わりませんでした。今回は、{ ...state, formErrors: [] } で新しいオブジェクトを返しているので、画面は変わります。しかし、明細の配列は同じものなので、保存のエフェクトは動きません（第6章の 6.2）。

チェックリスト

  • key に index を使うと、行を削除したときに何が起きるかを説明できる
  • state の配列に push すると、開発中に同じ明細が 2 つ入る理由を説明できる
  • 差分の中の「機能の本体」と「ついでの変更」を分けて読む理由を説明できる

React 編を終えて

DOM 版で自分で書いていた「状態を入れ替える」「画面を作り直す」を、React が引き受けています。その代わりに、次の 3 つの決まりを守ります。

  • state は書き換えずに、新しく作る
  • 表示する値は、state から計算する
  • React の外にあるもの（保存先など）を state に合わせる処理は、エフェクトに書く

実務の React のコードでは、この講座で扱っていない道具にも出会います。ページを切り替える仕組み、サーバーのデータを扱うライブラリ、React を土台にしたフレームワークなどです。名前と役割は、ツール一覧 にまとめてあります。
