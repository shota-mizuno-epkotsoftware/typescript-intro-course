この講座は、TypeScript とブラウザの基本に絞っています。周りのツールの多くは説明していません。このページでは、そうしたツールを役割ごとに並べます。使い方は書いていません。必要になったら、名前で調べてください。

ツールは 1〜2 年で入れ替わることがあります。名前より役割を覚えておくと、新しいツールに出会っても、どこに当たるかが分かります。

「講座での使い方」の欄は、講座の中で使ったものと、その使い方です。そのうち Node.js・npm・tsc の使い方は、本編 第0章 で説明しています。空欄のものは、講座では使いません。

実行と依存関係

役割 どんなときに必要になるか 例 講座での使い方
JavaScript ランタイム ブラウザの外で、JavaScript や TypeScript のコードを動かしたいとき Node.js、Deno、Bun Node.js（node ファイル.ts）
パッケージマネージャー ほかの人が作ったライブラリやツール（パッケージ）を入れ、その版をそろえたいとき。よく使うコマンドに名前を付けて動かすのにも使います npm、pnpm、Yarn npm（npm install、npm test など）

ほかのプロジェクトの package.json の scripts にも、似た名前が付いていることがあります。初めて見るプロジェクトでは、scripts を読むと起動や検査のコマンドを探せます。

名前 何をするか 中で動くものの例 講座での使い方
dev 開発用のサーバーを起動する Vite npm run dev M10
test テストを実行する（run を省ける） node:test、Vitest npm test M02
typecheck 型チェックだけをする tsc --noEmit npm run typecheck M02
build 公開用のファイルを作る Vite
lint リンターで書き方を検査する ESLint、Biome
format フォーマッターで見た目をそろえる Prettier、Biome

この講座の check は、typecheck と test を続けて動かします。

ビルド

役割 どんなときに必要になるか 例 講座での使い方
ビルドツール 開発中は、保存するたびにブラウザへ反映したいとき（開発サーバー）。公開するときは、ファイルをまとめて小さくしたいとき。型を消して JavaScript にしてからブラウザに渡すのも、ビルドツールの仕事です Vite Vite（npm run dev の開発サーバー）
バンドラー たくさんのファイルを、ブラウザに配りやすい少数のファイルにまとめたいとき。ビルドツールの中で使われることが多いです webpack、Rolldown

静的解析と整形

コードを実行せずに調べたり、見た目をそろえたりする道具です。

役割 どんなときに必要になるか 例 講座での使い方
型チェッカー 実行する前に、型の間違いを見つけたいとき。エディタの赤い波線も、同じ型チェックの結果です tsc tsc（npm run typecheck・npm run check の中）
リンター 間違いやすい書き方や、チームで決めた規則に合わない書き方を、エディタに警告として出したいとき ESLint、Biome
フォーマッター 字下げや改行などの見た目を、保存したときに自動でそろえたいとき Prettier、Biome

テスト

コードを動かして、期待どおりかを調べる道具です。

役割 どんなときに必要になるか 例 講座での使い方
テストランナー 関数が期待どおりの値を返すかを、まとめて自動で検査したいとき node:test、Vitest、Jest node:test（npm test の中。Node.js に付いている）
E2E テスト 本物のブラウザを自動で操作して、入力やボタンの操作まで含めた画面の動きを検査したいとき（E2E は End to End の略で、端から端まで、という意味です） Playwright、Cypress

UI

役割 どんなときに必要になるか 例 講座での使い方
UI ライブラリ・フレームワーク 画面を部品（コンポーネント）に分けて作り、状態が変わったら表示を自動で作り直したいとき React、Vue、Svelte React（React 編で使う）
メタフレームワーク UI ライブラリの上に、ページの切り替え（ルーティング）や、サーバーで HTML を作る処理まで足して、アプリ全体を作りたいとき Next.js、Nuxt

サーバーと運用

役割 どんなときに必要になるか 例 講座での使い方
サーバー側の Web フレームワーク API など、サーバーで動く処理を TypeScript で書きたいとき Hono、Express
CI（継続的インテグレーション） 変更を送るたびに、型チェックやテストを自動で動かし、壊れていないかを検査したいとき GitHub Actions
