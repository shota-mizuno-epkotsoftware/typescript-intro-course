地図：画面・ファイル・操作のたびに繰り返す流れ

最初に完成版を起動し、ブラウザで明細の追加・絞り込み・削除と、ページの読み込み直しを試します。

npm run dev app

ファイルの名前は、役割を表しています。 名前から見当を付けてから開くと、読む範囲を絞れます。practice/app/src/ の主なファイルは次のとおりです（.test.ts で終わるファイルはテスト）。

アプリの状態（画面を作るためにアプリが覚えている値）は、main.ts の変数 state 1 つにまとめてあります。操作のたびに、新しい状態を作って入れ替え、画面を作り直します。

要点

操作から、画面が変わるまで

イベントの処理は、state.ts の関数で新しい状態を作り、update に渡します。月の選択欄を変えたときの処理は、次の 3 行です。

practice/app/src/main.ts（70〜72行目）

elements.filterMonth.addEventListener("change", () => {
  update(setFilter(state, { month: elements.filterMonth.value }));
});

update が状態を入れ替え、render を呼びます。

practice/app/src/main.ts（20〜27行目）

// 状態を新しくし、明細が変わっていれば保存して、画面を作り直す
function update(next: AppState): void {
  if (next.entries !== state.entries) {
    saveEntries(next.entries);
  }
  state = next;
  render(state, elements);
}

render は、表示する明細を filterEntries で 1 回だけ選び、集計と一覧の両方に渡します。

practice/app/src/render.ts（104〜110行目）

export function render(state: AppState, elements: Elements): void {
  const visibleEntries = filterEntries(state.entries, state.filter);
  renderForm(state, elements);
  renderFilter(state, elements);
  renderSummary(visibleEntries, elements);
  renderList(visibleEntries, elements);
}

型を地図にする

明細の型 Entry は、収入（Income）と支出（Expense）のユニオン型で、kind で見分けます（判別可能なユニオン型）。 収入だけが入金元 source を、支出だけが分類 category を持ちます。

practice/app/src/types.ts（1〜19行目）

export type Income = {
  kind: "income";
  id: string;
  date: string;
  amount: number;
  source: string;
  memo?: string;
};

export type Expense = {
  kind: "expense";
  id: string;
  date: string;
  amount: number;
  category: string;
  memo?: string;
};

export type Entry = Income | Expense;

if で kind を調べると、entry の型が絞り込まれます（本編第6章）。下の 14 行目の entry は Income 型、16 行目では Expense 型です。

practice/app/src/format.ts（12〜17行目）

export function entryLabel(entry: Entry): string {
  if (entry.kind === "income") {
    return entry.source;
  }
  return entry.category;
}

型の定義から、その型の値を作る場所・使う場所をたどると、直す場所が見つかります（改修 1）。

絞り込みと集計は、配列のメソッドをつなぐ

summary.ts の関数は、filter や reduce をつないで書いてあります。下の filterEntries は、月の条件と種別の条件を 1 つずつ filter にしています。monthOf は、日付から "2026-11" の形の月を取り出す関数です。

practice/app/src/summary.ts（23〜27行目）

export function filterEntries(entries: Entry[], filter: Filter): Entry[] {
  return entries
    .filter((entry) => filter.month === "all" || monthOf(entry.date) === filter.month)
    .filter((entry) => filter.kind === "all" || entry.kind === filter.kind);
}

関数が何を返すべきかは、テストのファイル（summary.test.ts）に書いてあります。テストは仕様として読めます（問題 4）。

外から来るデータは、検査してから使う

入力欄の値、保存した明細、通信の結果は、型どおりとは限りません。検査を通ったものだけを使います。 型は実行時に消えるので、型注釈を書いても、実行時の値は調べられません。

  • 入力欄の値は、数字を入力しても文字列です。validate.ts が数値に変換して検証し、明細を作ります。
  • 保存した明細と通信の結果は、unknown 型で受け取り、typeof などで検査します。

practice/app/src/storage.ts（31〜44行目）

export function parseStoredEntries(text: string | null): Entry[] {
  if (text === null) {
    return [];
  }
  try {
    const data: unknown = JSON.parse(text);
    if (!Array.isArray(data)) {
      return [];
    }
    return data.map(toEntry).filter((entry) => entry !== null);
  } catch {
    return [];
  }
}

toEntry は、1 件ずつ項目を調べ、正しい形なら明細を、そうでなければ null を返します。

  • JSON.parse が読めない文字列でエラーを投げると、catch へ移って [] を返します（本編第9章。中身を使わないので (e) を省いています）。最後の .filter((entry) => entry !== null) は、toEntry が null を返した要素を除きます。

変更は、必要な変更とついでの変更に分けて読む

ほかの人の変更は、差分で読みます。機能に必要な変更と、ついでに行われた整理を分け、ついでの変更で動きが変わっていないかを調べます。実際の差分は、改修 3 の問題 3 で読みます。

改修 1：支出に「固定費」の項目を足す

支出の明細に、固定費かどうかを表す項目 fixed を足し、一覧で「交通費（固定費）」のように表示します。固定費は、家賃や定期券など、毎月決まって出ていくお金です。改修用フォルダは practice/exercises/P02-types/（章ID は P02）です。

問題 1

型の定義を読んだら、次に「その型の値をどこで作っているか」を探します。

  1. Entry 型の値を新しく作っている関数は、アプリの中に 2 つあります。1 つは storage.ts の toEntry で、保存されたデータから明細を作ります。もう 1 つは、どのファイルの、何という関数ですか。
    • 探し方：types.ts の Entry の上で「参照へ移動」を使います。参照は多く出るので、ファイルの役割の表から見当を付けて開きます。
    • 選ぶのは、明細のオブジェクトを書いて返している関数です。Entry を受け取るだけの関数は選びません。テストのファイルと testdata.ts は除きます。
  2. toEntry の次の抜粋を読み、memo のある支出のデータを読み込んだとき、26 行目で返す明細が持つプロパティを、すべて挙げてください。

practice/app/src/storage.ts（20〜27行目）

  const common = typeof memo === "string" ? { id, date, amount, memo } : { id, date, amount };

  if (kind === "income" && typeof source === "string") {
    return { kind, ...common, source };
  }
  if (kind === "expense" && typeof category === "string") {
    return { kind, ...common, category };
  }
  • kind・memo・category などの変数は、12 行目の const { kind, id, date, amount, source, category, memo } = record; で、保存されたデータから取り出した値です（分割代入。本編第4章）。型は unknown です。
  • ...common は、common の中身をコピーするスプレッド構文です（本編第4章）。
答えと解説
  1. validate.ts の parseEntryForm です。フォームの入力から明細を作ります。

practice/app/src/validate.ts（56〜61行目）

  const entry: Entry =
    kind === "income"
      ? { kind: "income", id, date, amount, source }
      : { kind: "expense", id, date, amount, category };

  return { ok: true, entry: memo === "" ? entry : { ...entry, memo } };

明細が生まれるのは、アプリの外からデータが入ってくる 2 か所です。ほかの場所は、できあがった Entry を受け取って使います。

  1. kind・id・date・amount・memo・category の 6 つです。memo が文字列なので、20 行目の common は { id, date, amount, memo } です。26 行目は、kind と common の中身と category を並べたオブジェクトを返します。

どちらの関数も、収入と支出のオブジェクトを別々に書いています。支出に項目を足すときは、2 つの関数の支出の側を直します。

フォームの側（チェック欄の HTML、要素の取得、入力の読み取り）は、改修用フォルダに用意してあります。足すのは、型と、その型の値を作る場所・使う場所です。

呼び出し 返す値

ヒント 1：どこを見ればよいか

  • storage.ts：問題 1 の 2 の抜粋の、支出の明細を返している行

ヒント 2：書き出し

テストや画面がうまくいかないとき
表示 よくある原因
型チェックで 'fixed' does not exist in type 'Expense'（testdata.ts、state.test.ts） types.ts の Expense に、まだ fixed を足していません
型チェックで Unused '@ts-expect-error' directive.（validate.test.ts） Expense に fixed を足していないか、fixed?: boolean と ? を付けています。types.ts を直しても新しい型エラーが出ないときも、? を付けていないかを確かめます
型チェックのエラーの最後の行が Property 'fixed' is missing in type '{ ... }' but required in type 'Expense'. そのファイルで作っている支出の明細に fixed がありません（validate.ts で直す行は、手順 3）
型チェックで No value exists in scope for the shorthand property 'fixed'. { ..., fixed } と短く書いていますが、fixed という名前の変数がありません。validate.ts では fixed: input.fixed と書きます
型チェックで Type 'unknown' is not assignable to type 'boolean'.（storage.ts） 保存されたデータの fixed を、確かめずにそのまま入れています。fixed === true にします
型チェックで 'fixed' does not exist in type 'Income'（validate.ts） 収入の明細にも fixed を入れています
型チェックで Property 'fixed' does not exist on type 'Entry'.（format.ts） kind を確かめる前に entry.fixed を読んでいます。Expense に絞り込まれた後で読みます
テストで + fixed: false - fixed: true、または + fixed: true - fixed: false（parseEntryForm） fixed に、入力の値ではなく決まった値を入れています

テスト「fixed が true でも false でもない支出…」が失敗する Boolean(fixed) のように、true 以外の値も true にしています。fixed === true にします。差分が + [] のときは、支出を捨てています（下の行）
テスト「fixed のない支出…を、fixed が false の支出として読む」が失敗し、期待する明細が - の行で丸ごと表示される fixed がない支出を捨てています。typeof fixed === "boolean" を条件に足すと、こうなります
テストで + '交通費' - '交通費（固定費）' entryLabel を、まだ直していません

practice/solutions/P02-types/src/validate.ts

import type { Entry } from "./types.ts";

export type FormInput = {
  kind: string;
  date: string;
  amount: string;
  category: string;
  fixed: boolean;
  source: string;
  memo: string;
};

export type ParseResult = { ok: true; entry: Entry } | { ok: false; errors: string[] };

export function isValidDate(text: string): boolean {
  return /^\d{4}-\d{2}-\d{2}$/.test(text);
}

export function isValidAmount(amount: number): boolean {
  return Number.isInteger(amount) && amount >= 1;
}

export function parseAmount(text: string): number | null {
  const amount = Number(text);
  return isValidAmount(amount) ? amount : null;
}

export function parseEntryForm(input: FormInput, id: string): ParseResult {
  const { kind, date } = input;
  const amount = parseAmount(input.amount);
  const category = input.category.trim();
  const source = input.source.trim();
  const memo = input.memo.trim();

  const errors: string[] = [];
  if (kind !== "income" && kind !== "expense") {
    errors.push("種別を選んでください");
  }
  if (!isValidDate(date)) {
    errors.push("日付を入力してください");
  }
  if (amount === null) {
    errors.push("金額は 1 以上の整数で入力してください");
  }
  if (kind === "expense" && category === "") {
    errors.push("分類を選んでください");
  }
  if (kind === "income" && source === "") {
    errors.push("入金元を入力してください");
  }

  // 間違いがあれば、明細を作らずに返す
  if (errors.length > 0 || amount === null) {
    return { ok: false, errors };
  }

  const entry: Entry =
    kind === "income"
      ? { kind: "income", id, date, amount, source }
      : { kind: "expense", id, date, amount, category, fixed: input.fixed };

  return { ok: true, entry: memo === "" ? entry : { ...entry, memo } };
}

import type { Entry } from "./types.ts";
import { isValidAmount, isValidDate } from "./validate.ts";

const STORAGE_KEY = "kakeibo:entries";

function toEntry(value: unknown): Entry | null {
  if (typeof value !== "object" || value === null) {
    return null;
  }
  // プロパティを名前で読めるように、Record 型の変数にコピーする
  const record: Record<string, unknown> = { ...value };
  const { kind, id, date, amount, source, category, fixed, memo } = record;

  if (typeof id !== "string" || typeof date !== "string" || !isValidDate(date)) {
    return null;
  }
  if (typeof amount !== "number" || !isValidAmount(amount)) {
    return null;
  }
  const common = typeof memo === "string" ? { id, date, amount, memo } : { id, date, amount };

  if (kind === "income" && typeof source === "string") {
    return { kind, ...common, source };
  }
  if (kind === "expense" && typeof category === "string") {
    // 項目を足す前に保存したデータには fixed がないので、false として扱う
    return { kind, ...common, category, fixed: fixed === true };
  }
  return null;
}

export function parseStoredEntries(text: string | null): Entry[] {
  if (text === null) {
    return [];
  }
  try {
    const data: unknown = JSON.parse(text);
    if (!Array.isArray(data)) {
      return [];
    }
    return data.map(toEntry).filter((entry) => entry !== null);
  } catch {
    return [];
  }
}

export function loadEntries(): Entry[] {
  return parseStoredEntries(localStorage.getItem(STORAGE_KEY));
}

export function saveEntries(entries: Entry[]): void {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(entries));
}

practice/solutions/P07-changes/src/summary.ts

import { entryLabel } from "./format.ts";
import type { Entry, EntryKind, Filter } from "./types.ts";

export type CategoryTotal = {
  category: string;
  total: number;
};

export function monthOf(date: string): string {
  return date.slice(0, 7);
}

export function listMonths(entries: Entry[]): string[] {
  const months: string[] = [];
  for (const entry of entries) {
    const month = monthOf(entry.date);
    if (!months.includes(month)) {
      months.push(month);
    }
  }
  return months.sort().reverse();
}

function matchesKeyword(entry: Entry, keyword: string): boolean {
  return entryLabel(entry).includes(keyword) || (entry.memo ?? "").includes(keyword);
}

export function filterEntries(entries: Entry[], filter: Filter): Entry[] {
  return entries
    .filter((entry) => filter.month === "all" || monthOf(entry.date) === filter.month)
    .filter((entry) => filter.kind === "all" || entry.kind === filter.kind)
    .filter((entry) => matchesKeyword(entry, filter.keyword));
}

export function sortByDate(entries: Entry[]): Entry[] {
  return [...entries].sort((a, b) => b.date.localeCompare(a.date));
}

export function totalOf(entries: Entry[], kind: EntryKind): number {
  return entries
    .filter((entry) => entry.kind === kind)
    .reduce((sum, entry) => sum + entry.amount, 0);
}

export function balanceOf(entries: Entry[]): number {
  return totalOf(entries, "income") - totalOf(entries, "expense");
}

export function totalsByCategory(entries: Entry[]): CategoryTotal[] {
  const totals = new Map<string, number>();
  for (const entry of entries) {
    if (entry.kind === "expense") {
      totals.set(entry.category, (totals.get(entry.category) ?? 0) + entry.amount);
    }
  }
  return [...totals]
    .map(([category, total]) => ({ category, total }))
    .sort((a, b) => b.total - a.total);
}

import type { Elements } from "./elements.ts";
import { entryLabel, formatMonth, formatSignedYen, formatYen } from "./format.ts";
import { balanceOf, filterEntries, listMonths, sortByDate, totalOf, totalsByCategory } from "./summary.ts";
import type { AppState, Entry } from "./types.ts";

function createOption(value: string, label: string): HTMLOptionElement {
  const option = document.createElement("option");
  option.value = value;
  option.textContent = label;
  return option;
}

function createText(tag: string, text: string, className = ""): HTMLElement {
  const element = document.createElement(tag);
  element.textContent = text;
  element.className = className;
  return element;
}

// 選択肢を入れ替える。入れ替える前に選ばれていた値が新しい選択肢にもあれば、選び直す
function replaceOptions(select: HTMLSelectElement, options: HTMLOptionElement[]): void {
  const selected = select.value;
  select.replaceChildren(...options);
  if (options.some((option) => option.value === selected)) {
    select.value = selected;
  }
}

function categoryStatusText({ categories }: AppState): string {
  if (categories.status === "loading") {
    return "分類を読み込んでいます…";
  }
  if (categories.status === "error") {
    return categories.message;
  }
  return "";
}

function renderForm(state: AppState, elements: Elements): void {
  const isExpense = state.formKind === "expense";
  elements.kind.value = state.formKind;
  elements.categoryField.classList.toggle("hidden", !isExpense);
  elements.sourceField.classList.toggle("hidden", isExpense);

  const { categories } = state;
  if (categories.status === "ready") {
    replaceOptions(elements.category, categories.items.map((item) => createOption(item, item)));
  }
  elements.categoryStatus.textContent = categoryStatusText(state);
  elements.categoryStatus.classList.toggle("error", categories.status === "error");

  elements.formErrors.replaceChildren(...state.formErrors.map((message) => createText("li", message)));
}

function renderFilter(state: AppState, elements: Elements): void {
  const months = listMonths(state.entries);
  elements.filterMonth.replaceChildren(
    createOption("all", "すべて"),
    ...months.map((month) => createOption(month, formatMonth(month))),
  );
  elements.filterMonth.value = state.filter.month;
  elements.filterKind.value = state.filter.kind;
  // 入力の途中（日本語の変換中など）に値を入れ直さないよう、違うときだけ入れる
  if (elements.filterKeyword.value !== state.filter.keyword) {
    elements.filterKeyword.value = state.filter.keyword;
  }
}

function renderSummary(entries: Entry[], elements: Elements): void {
  const balance = balanceOf(entries);
  elements.totalIncome.textContent = formatYen(totalOf(entries, "income"));
  elements.totalExpense.textContent = formatYen(totalOf(entries, "expense"));
  elements.balance.textContent = formatYen(balance);
  elements.balance.className = balance < 0 ? "negative" : "positive";

  elements.categoryTotals.replaceChildren(
    ...totalsByCategory(entries).map(({ category, total }) =>
      createText("li", `${category}: ${formatYen(total)}`),
    ),
  );
}

function createEntryItem(entry: Entry): HTMLElement {
  const description = document.createElement("span");
  description.append(createText("span", entryLabel(entry), "label"));
  if (entry.memo !== undefined) {
    description.append(createText("span", ` ${entry.memo}`, "memo"));
  }

  const removeButton = createText("button", "削除", "remove");
  removeButton.dataset.id = entry.id;

  const item = document.createElement("li");
  item.append(
    createText("span", entry.date, "date"),
    description,
    createText("span", formatSignedYen(entry), `amount amount-${entry.kind}`),
    removeButton,
  );
  return item;
}

function renderList(entries: Entry[], elements: Elements): void {
  elements.entryList.replaceChildren(...sortByDate(entries).map(createEntryItem));
  elements.emptyMessage.classList.toggle("hidden", entries.length > 0);
}

export function render(state: AppState, elements: Elements): void {
  const visibleEntries = filterEntries(state.entries, state.filter);
  renderForm(state, elements);
  renderFilter(state, elements);
  renderSummary(visibleEntries, elements);
  renderList(visibleEntries, elements);
}
手順 3 の答え：なぜ、集計が変わらなかったのか

同僚は、検索の処理を、一覧を描く関数（renderList）の中に書いていました。一覧は絞り込まれますが、集計を描く関数には、検索する前の明細が渡されたままです。「見つからなかったとき」の表示も、検索する前の件数で決まっていました。

同僚の版  filterEntries（月・種別）         ─┬→ renderSummary（検索する前の明細）
                                             └→ renderList → メモで検索 → 一覧
直した版  filterEntries（月・種別・検索語） ─┬→ renderSummary
                                             └→ renderList

このアプリでは、「どの明細を表示するか」を filterEntries の 1 か所で決め、その結果を集計と一覧の両方に渡しています。同じ決まりを 2 か所に分けて書くと、片方だけが古いまま残ります。機能を足すときは、新しい場所を作る前に、同じ種類の処理がすでにどこにあるかを探します。

チェックリスト

  • 外から来るデータを unknown で受け取る理由と、型注釈だけでは実行時の値を調べられない理由を説明できる
  • 検索の処理を renderList に書くと、集計が変わらない理由を説明できる
  • 差分の中の「ついで」の変更で動きが変わっていないかを、どう調べるかを説明できる
