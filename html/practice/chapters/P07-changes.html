7.1 この章の進め方

この章では、どのファイルをどの順で読むかを自分で選びます。使える読み方は、次のとおりです。

読み方 扱った章
動かしてから読む、ファイルの名前から見当を付ける、全文検索で探す 第1章
型の定義から、作る場所と使う場所をたどる（定義へ移動、参照へ移動） 第2章
node で関数を呼んで確かめる 第3章
イベントからたどる、開発者ツールで要素とクラスを見る、debugger; で止める、差分を読む 第4章
テストを仕様として読む 第5章
開発者ツールで、保存されたデータと通信を見る 第6章

場面の設定：同僚が、家計簿のアプリに「検索」の機能を足しました。絞り込みの欄に入力欄が増え、文字を入れると、その文字を含む明細だけが一覧に表示されます。あなたは、この変更を読んで確かめる役です。

フォルダ 中身
practice/app/ 変更の前（これまで読んできた完成版）
practice/exercises/P07-changes/ 変更の後（検索の機能が入った版）。この章の改修用フォルダでもあります

npm run dev P07 で起動して、検索の欄を使います。メモを「昼食」にした支出を 1 件追加し、検索の欄に「昼」と入れます。結果を見たら、画面を Ctrl + C で止めます。

次のコマンドで、変更の前と後の差分を表示できます（--no-index は、2 つのフォルダやファイルを直接比べる指定です）。フォルダ全体の差分には改修で探す箇所も入っているので、このコマンドは章末の改修で使います。問題では、本文に載せた差分を読みます。

git diff --no-index practice/app practice/exercises/P07-changes

ファイルを 1 つだけ比べるときは、2 つのファイルの名前を並べます。

git diff --no-index practice/app/src/state.ts practice/exercises/P07-changes/src/state.ts

表示が長いときは、q キーで終わります。

本文の差分は、ファイル名を示す行（diff --git〜+++）を省き、@@ の行から載せています。

確かめ方：1 の予測は、問題 2〜4 の差分と見比べます。

ここでは、一部のファイルの差分を読みます。残りのファイルの差分は、章末の改修の中で、自分で表示して読みます。

この 1 行だけを足して、ほかのファイルを変えなかったとすると、完成版のどこに型エラーが出ますか。Filter 型の値を作っている場所を探して、答えてください。

答えと解説

Property 'keyword' is missing in type '{ month: string; kind: "all"; }' but required in type 'Filter'.

summary.test.ts にも、同じ形のエラーが出ます（kind の型の部分だけが違います）。

keyword は省略できない項目なので、Filter を作っている場所すべてに型エラーが出ます。第2章の改修で体験した、「型を変えると、直す場所を型チェックが教えてくれる」のと同じです。

setFilter の引数の型は Partial<Filter>（一部の項目だけでよい）なので、main.ts の setFilter(state, { month: ... }) には型エラーが出ません。state.test.ts の filter: { month: "all", kind: "all" } は、比べる値として書いているだけです。Filter 型の変数に入れていないので、型エラーになりません。

確かめ方：改修用フォルダの src/state.ts の 4 行目で、keyword: "" を消します。その行に赤い波線が出ます。

この差分には、2 種類の変更が入っています。

  • 検索語を足すのに、必要な変更
  • 「ついでに」行われた、コードの整理

  2. 「ついで」の変更で、画面の動きが変わる場面があります。どんな操作をしたときに、何が変わりますか。removeEntry の、変更の前と後の式を見比べて答えてください。
答えと解説
  1. 必要な変更は、最初の状態の filter に keyword: "" を足すことです（noFilter を作って、createInitialState で使っている部分）。「ついで」の変更は removeEntry の最後の行です。「絞り込みなし」を表す noFilter ができたので、ここでも使うように書き換えています。
  2. 月で絞り込んでいて、その月の最後の明細を削除したときです。変更の前は、月の絞り込みだけが外れていました。変更の後は、種別の絞り込みと検索語まで外れます。

削除の前の state.filter "2027-01" "expense" "テスト"
変更の前 { ...state.filter, month: "all" } "all" "expense" "テスト"
変更の後 noFilter "all" "all" ""

確かめ方：npm run dev P07 の画面で、次の順に試します。

  1. 月の選択欄にまだない月（2027 年 1 月など）の日付で、メモが「テスト」の支出を 1 件追加する
  2. 月をその月、種別を「支出」にし、検索の欄に「テスト」と入れる
  3. その支出を削除する。種別が「すべて」に戻り、検索の欄も空になります

正しい動き（種別の「支出」と検索の「テスト」が残る）は、章末の改修を終えた後に同じ手順で確かめます。

問題 6

最後は、コードを書かずに設計を考える問いです。

このアプリに「明細を編集する」機能を足すとします。一覧の「編集」ボタンを押すと、その明細の内容がフォームに入り、直して保存できる機能です。これまでに読んだ構造に合わせるなら、どのファイルに、何を足しますか。分かる範囲で、箇条書きにしてください。

答えの例

自分の答えは、この後の「次の形に当てはめて考える」の 4 つで見直します。4 つのそれぞれに当たる変更が、自分の答えに入っていれば十分です。ファイルの名前や関数の名前が答えの例と違っていても構いません。

  • types.ts：AppState に、「今、編集している明細の id（編集していなければ null）」を足す
  • state.ts：編集を始める関数（編集する明細の id を入れ、formKind をその明細の種別にする）、明細を置き換える関数（id が同じ明細を、新しい明細に入れ替えた配列を作る）を足す
  • render.ts：createEntryItem に「編集」ボタンを足す（data-id を付ける）。renderForm で、編集中かどうかで、ボタンの文言を「追加」か「保存」に変える
  • main.ts：一覧の click の処理で、「削除」と「編集」のどちらのボタンかを見分ける。「編集」なら、その id の明細を探し、日付・金額などを入力欄に入れる。submit の処理で、編集中なら、その明細の id を parseEntryForm に渡して、追加ではなく置き換えを呼ぶ
  • validate.ts：変えない。入力の検証は、追加でも編集でも同じ
  • storage.ts：変えない。明細の配列が変われば、update が保存する
  • テスト：state.test.ts に、置き換える関数のテストを足す

次の形に当てはめて考えます。細かな点は違っていて構いません。

  1. 画面に出すものを、状態に足す
  2. 状態を新しくする関数を足す
  3. 状態から画面を作る部分を直す
  4. イベントから、その関数を呼ぶ

入力欄に明細の内容を入れる部分だけは、この形に収まりません。このアプリは、入力途中の値を状態に持たず、入力欄が持っています（main.ts は「追加」が押されたときに入力欄から値を読みます）。render の中で入れると、描き直すたびに入力途中の値が明細の値に戻ってしまいます。そのため、「編集」が押されたときに 1 回だけ入れます。

まとめ

ほかの人の変更を読むときに確かめることを、4 つ以上挙げてください。

答えの例
  • 変更されたファイルの一覧を見て、変更の大きさと、手の入った場所をつかむ。変わっているはずなのに、変わっていないファイルがないか
  • 1 つずつの差分で、その行が変更の前と後で何をするかを言葉にする
  • 機能に必要な変更と、ついでの整理を分ける。ついでの整理で、動きが変わっていないか
  • これまでのコードと、同じ形で書かれているか。違う所があれば、理由があるか
  • テストが足されているか。なければ、仕様をテストとして書いてみる
  • 型チェックとテストを実行し、画面でも、足した機能とこれまでの機能の両方を試す

改修：検索の機能を仕上げる

同僚の変更について、次の 3 つを行います。

削除の不具合（差分で入ったもの）：問題 4 で見つけた、removeEntry の不具合を直します。

検索の不具合（利用者からの報告）：次の報告が届いています。原因の場所は自分で探してください。

  • メモで検索すると、一覧は絞り込まれるのに、上の集計（収入・支出・収支）の金額が変わりません。月や種別で絞り込んだときは、集計も変わるのに。
  • それと、検索して 1 件も見つからなかったとき、一覧が空になるだけで、何も表示されません。

検索の対象を広げる（小さな機能）：メモだけでなく、分類（支出）と入金元（収入）も検索します。

進め方

  1. 準備手順 1
  2. 削除の不具合を直す手順 2
  3. 検索の不具合を直す手順 3〜5
  4. 検索の対象を広げる手順 6
  5. 仕上げる手順 7〜11

準備手順 1

  1. テストを実行し、失敗しているテストを見る

    • 画面を起動していたら、先に Ctrl + C で止めます
    npm test P07
    • こうなれば OK「--- 失敗の内容 ---」より上に、✖ で始まる行が 5 つある

削除の不具合を直す手順 2

import { monthOf } from "./summary.ts";
import type { AppState, CategoriesState, Entry, EntryKind, Filter } from "./types.ts";

const noFilter: Filter = { month: "all", kind: "all", keyword: "" };

export function createInitialState(entries: Entry[]): AppState {
  return {
    entries,
    filter: noFilter,
    categories: { status: "loading" },
    formKind: "expense",
    formErrors: [],
  };
}

export function addEntry(state: AppState, entry: Entry): AppState {
  return { ...state, entries: [...state.entries, entry], formErrors: [] };
}

export function removeEntry(state: AppState, id: string): AppState {
  const entries = state.entries.filter((entry) => entry.id !== id);
  const { month } = state.filter;
  const monthRemains = month === "all" || entries.some((entry) => monthOf(entry.date) === month);
  return {
    ...state,
    entries,
    filter: monthRemains ? state.filter : { ...state.filter, month: "all" },
  };
}

export function setFilter(state: AppState, changes: Partial<Filter>): AppState {
  return { ...state, filter: { ...state.filter, ...changes } };
}

export function setCategories(state: AppState, categories: CategoriesState): AppState {
  return { ...state, categories };
}

export function setFormKind(state: AppState, formKind: EntryKind): AppState {
  return { ...state, formKind, formErrors: [] };
}

export function setFormErrors(state: AppState, formErrors: string[]): AppState {
  return { ...state, formErrors };
}

practice/solutions/P07-changes/src/summary.ts

import { entryLabel } from "./format.ts";
import type { Entry, EntryKind, Filter } from "./types.ts";

export type CategoryTotal = {
  category: string;
  total: number;
};

export function monthOf(date: string): string {
  return date.slice(0, 7);
}

export function listMonths(entries: Entry[]): string[] {
  const months: string[] = [];
  for (const entry of entries) {
    const month = monthOf(entry.date);
    if (!months.includes(month)) {
      months.push(month);
    }
  }
  return months.sort().reverse();
}

function matchesKeyword(entry: Entry, keyword: string): boolean {
  return entryLabel(entry).includes(keyword) || (entry.memo ?? "").includes(keyword);
}

export function filterEntries(entries: Entry[], filter: Filter): Entry[] {
  return entries
    .filter((entry) => filter.month === "all" || monthOf(entry.date) === filter.month)
    .filter((entry) => filter.kind === "all" || entry.kind === filter.kind)
    .filter((entry) => matchesKeyword(entry, filter.keyword));
}

export function sortByDate(entries: Entry[]): Entry[] {
  return [...entries].sort((a, b) => b.date.localeCompare(a.date));
}

export function totalOf(entries: Entry[], kind: EntryKind): number {
  return entries
    .filter((entry) => entry.kind === kind)
    .reduce((sum, entry) => sum + entry.amount, 0);
}

export function balanceOf(entries: Entry[]): number {
  return totalOf(entries, "income") - totalOf(entries, "expense");
}

export function totalsByCategory(entries: Entry[]): CategoryTotal[] {
  const totals = new Map<string, number>();
  for (const entry of entries) {
    if (entry.kind === "expense") {
      totals.set(entry.category, (totals.get(entry.category) ?? 0) + entry.amount);
    }
  }
  return [...totals]
    .map(([category, total]) => ({ category, total }))
    .sort((a, b) => b.total - a.total);
}

practice/solutions/P07-changes/src/render.ts

import type { Elements } from "./elements.ts";
import { entryLabel, formatMonth, formatSignedYen, formatYen } from "./format.ts";
import { balanceOf, filterEntries, listMonths, sortByDate, totalOf, totalsByCategory } from "./summary.ts";
import type { AppState, Entry } from "./types.ts";

function createOption(value: string, label: string): HTMLOptionElement {
  const option = document.createElement("option");
  option.value = value;
  option.textContent = label;
  return option;
}

function createText(tag: string, text: string, className = ""): HTMLElement {
  const element = document.createElement(tag);
  element.textContent = text;
  element.className = className;
  return element;
}

// 選択肢を入れ替える。入れ替える前に選ばれていた値が新しい選択肢にもあれば、選び直す
function replaceOptions(select: HTMLSelectElement, options: HTMLOptionElement[]): void {
  const selected = select.value;
  select.replaceChildren(...options);
  if (options.some((option) => option.value === selected)) {
    select.value = selected;
  }
}

function categoryStatusText({ categories }: AppState): string {
  if (categories.status === "loading") {
    return "分類を読み込んでいます…";
  }
  if (categories.status === "error") {
    return categories.message;
  }
  return "";
}

function renderForm(state: AppState, elements: Elements): void {
  const isExpense = state.formKind === "expense";
  elements.kind.value = state.formKind;
  elements.categoryField.classList.toggle("hidden", !isExpense);
  elements.sourceField.classList.toggle("hidden", isExpense);

  const { categories } = state;
  if (categories.status === "ready") {
    replaceOptions(elements.category, categories.items.map((item) => createOption(item, item)));
  }
  elements.categoryStatus.textContent = categoryStatusText(state);
  elements.categoryStatus.classList.toggle("error", categories.status === "error");

  elements.formErrors.replaceChildren(...state.formErrors.map((message) => createText("li", message)));
}

function renderFilter(state: AppState, elements: Elements): void {
  const months = listMonths(state.entries);
  elements.filterMonth.replaceChildren(
    createOption("all", "すべて"),
    ...months.map((month) => createOption(month, formatMonth(month))),
  );
  elements.filterMonth.value = state.filter.month;
  elements.filterKind.value = state.filter.kind;
  // 入力の途中（日本語の変換中など）に値を入れ直さないよう、違うときだけ入れる
  if (elements.filterKeyword.value !== state.filter.keyword) {
    elements.filterKeyword.value = state.filter.keyword;
  }
}

function renderSummary(entries: Entry[], elements: Elements): void {
  const balance = balanceOf(entries);
  elements.totalIncome.textContent = formatYen(totalOf(entries, "income"));
  elements.totalExpense.textContent = formatYen(totalOf(entries, "expense"));
  elements.balance.textContent = formatYen(balance);
  elements.balance.className = balance < 0 ? "negative" : "positive";

  elements.categoryTotals.replaceChildren(
    ...totalsByCategory(entries).map(({ category, total }) =>
      createText("li", `${category}: ${formatYen(total)}`),
    ),
  );
}

function createEntryItem(entry: Entry): HTMLElement {
  const description = document.createElement("span");
  description.append(createText("span", entryLabel(entry), "label"));
  if (entry.memo !== undefined) {
    description.append(createText("span", ` ${entry.memo}`, "memo"));
  }

  const removeButton = createText("button", "削除", "remove");
  removeButton.dataset.id = entry.id;

  const item = document.createElement("li");
  item.append(
    createText("span", entry.date, "date"),
    description,
    createText("span", formatSignedYen(entry), `amount amount-${entry.kind}`),
    removeButton,
  );
  return item;
}

function renderList(entries: Entry[], elements: Elements): void {
  elements.entryList.replaceChildren(...sortByDate(entries).map(createEntryItem));
  elements.emptyMessage.classList.toggle("hidden", entries.length > 0);
}

export function render(state: AppState, elements: Elements): void {
  const visibleEntries = filterEntries(state.entries, state.filter);
  renderForm(state, elements);
  renderFilter(state, elements);
  renderSummary(visibleEntries, elements);
  renderList(visibleEntries, elements);
}
コラム: なぜ、集計が変わらなかったのか（手順 3 で理由を考えてから開いてください）

同僚は、検索の処理を、一覧を描く関数（renderList）の中に書いていました。一覧は絞り込まれますが、集計を描く関数には、検索する前の明細が渡されたままです。「見つからなかったとき」の表示も、検索する前の件数で決まっていました。

同僚の版  filterEntries（月・種別）         ─┬→ renderSummary（検索する前の明細）
                                             └→ renderList → メモで検索 → 一覧
直した版  filterEntries（月・種別・検索語） ─┬→ renderSummary
                                             └→ renderList

このアプリでは、「どの明細を表示するか」を filterEntries の 1 か所で決め、その結果を集計と一覧の両方に渡しています（第1章の問題 7）。同じ決まりを 2 か所に分けて書くと、片方だけが古いまま残ります。機能を足すときは、新しい場所を作る前に、同じ種類の処理がすでにどこにあるかを探します。

チェックリスト

  • 変更されたファイルの一覧から、変更の全体と、気を付ける点の見当を付けられる
  • 差分の中から、機能に必要な変更と、ついでの変更を分けて読める
  • { ...state.filter, month: "all" } と noFilter の、意味の違いを説明できる

実践編を終えて

実践編では、1 つのアプリを次の順で読みました。

  1. 動かして、ファイルの地図を作り、入口から最初の表示までをたどる
  2. データの型を読み、作る場所と使う場所をたどる
  3. 入力が検査されて、明細になるまでを読む
  4. 操作によって状態が変わり、画面が作り直されるまでを読む
  5. 集計の処理を、テストと一緒に読む
  6. 外から来るデータを、確かめてから使う部分を読む
  7. ほかの人の変更を読み、直す

どの章でも中心にあったのは、「状態を変える → 状態から画面を作り直す」という形と、「外から来た値は、検査してから正しい型として扱う」という決まりです。
